# Two approaches to mastering ML and getting hired

**[Open original ↗](https://x.com/kmeanskaran/status/1882873136892555553)** · `Karan🧋` · 2025-01-24 · 24 replies · 1.5K likes · 72.8K views · ⭐ high follow-up

## 💬 Essence

OP frames mastering ML as two approaches: (1) maths, in-depth neural networks and transformer/stable-diffusion architectures, and (2) fine-tuning, API gateways, agents and ML system design. His self-thread advises keeping them separate with different time budgets - 1 hour/day on skill 1, 4 hours/day on skill 2 - prioritising skill 2 for the resume because skill 1 is the long game ('just skill 2 makes you an Uber driver, skill 1 too makes you an F1 driver'), while insisting it's '1 and 2 both', MLOps is critical, statistics matter for feature engineering, and he spends weekends on path 1 plus side projects with agentic frameworks. Replies add a third track (MLOps: deploy, scale, monitor), warn that everyone does track 2 so track 1 is the differentiator (token-mismatch bugs betray missing fundamentals), and ask for fine-tuning GitHub projects.

## 💡 Takeaway

Clear theory-vs-applied learning framework; the consensus that you need both tracks is the takeaway.
