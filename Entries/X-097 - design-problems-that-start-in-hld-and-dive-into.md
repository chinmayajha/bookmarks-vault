# Design problems that start in HLD and dive into low-level code

**[Open original ↗](https://x.com/pulkit_mittal_/status/2006684446926450987)** · `pulkit mittal` · 2025-12-31 · 4 replies · 28 reposts · 283 likes · 79.4K views · 515 bookmarks

## 💬 Essence

Pulkit says good design rounds start with HLD and then dive into low-level implementation, so he lists problems covering both: rate limiter (token/leaky bucket strategies + distributed counters, consistency, clock skew), in-memory Redis-like cache (eviction + sharding, replication, persistence), message queue (observer pattern + ordering, durability, backpressure), notification system (retry logic + fan-out, failure handling), job scheduler (worker pool + Kafka, fault tolerance), URL shortener (idempotency + ID generation) and more. It quote-posts his LLD sheet; no discussion is captured; 283 likes and 515 bookmarks.

## 💡 Takeaway

A problem set spanning both halves of a design round - the pairing most interviewers actually run.
