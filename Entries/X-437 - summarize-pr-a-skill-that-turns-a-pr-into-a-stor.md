# /summarize-pr: a skill that turns a PR into a story of code and decisions

**[Open original ↗](https://x.com/pabcrab/status/2124615831900369326)** · `Pablo Caballero` · 2026-11-22 · 29 replies · 19 reposts · 1,080 likes · 1,844 bookmarks · 98K views · 🎬

## 💬 Essence

Pablo Caballero says he reviews PRs 5x faster with /summarize-pr, a skill in the MeLlamoPablo/skills repo. His idea: only about 20% of the code is important and 80% is mechanical, and AI reviewers check that the 80% follows the 20%. The skill makes a page that mixes the code with the reason for each change, and it lists implicit decisions with their own UI. The PR description stays human-written, and the skill removes AI slop from it. He also uses it to write walkthroughs of his own PRs and sends colleagues the summary. He plans to auto-run it when he is tagged on a PR. He says Opus 5.5 was the turning point, but humans still own high-level decisions. Replies doubt it. One says to let AI summarize and skip the code. He answers that he wants to read the key code with the boring parts removed. The skill is opinionated about what counts as important.

## 💡 Takeaway

A review workflow that focuses on the 20% of code that matters. Tune what counts as important for your project.
