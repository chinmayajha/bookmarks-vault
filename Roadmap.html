Inference Engineering Roadmap

24 weeks5 Oct 2026 → 21 Mar 2027~10–12 hrs/week

No single course takes you all the way to inference engineer. The spine stays CS336 → GPU/CUDA → CS229S/GPU MODE → vLLM → capstone. The added resources are used as labs, references and implementation guides—not as extra courses. Every phase ends with something built and measured.

Use two weekday sessions for learning and one longer weekend block for code. Prefer implementation, profiling and benchmarking over passive completion; pause rather than skipping ahead when exams or deadlines hit.

The plan

  1. Weeks 1–25 Oct – 18 Oct

    PyTorch and transformer foundations

    Work through the PyTorch tutorials only as far as tensors, autograd, modules, GPU execution and basic profiling. Read chapters 2–4 of Raschka's Build a Large Language Model (From Scratch). Before coding, run Karpathy's microGPT once to see the smallest complete GPT training/inference loop. Then implement your own tiny GPT in PyTorch.

    Done whenyou can write the model, run it on GPU, and explain what PyTorch is adding for efficiency.
  2. Weeks 3–819 Oct – 29 Nov

    Stanford CS336, the core course

    CS336: Language Modeling from Scratch: lectures 1–10, Assignment 1 (transformer), then Assignment 2 (profiling/benchmarking, FlashAttention-2 in Triton, memory-efficient distributed version). Skip data, pretraining and alignment for now. Use 100 Days of Inference selectively for matching low-level exercises; do not treat it as a second syllabus.

    Done whenA1 and A2 pass, and you can explain FLOPs, memory traffic, arithmetic intensity and the bottleneck of your own model.
  3. Weeks 9–1430 Nov – 10 Jan

    GPUs and CUDA

    Keep Programming Massively Parallel Processors as the architecture text. For hands-on CUDA, use Elliot Arledge's CUDA course as the faster practical path; use the Coursera GPU Programming Specialization only to fill gaps. Write vector add, reduction, softmax and tiled matmul, then profile against cuBLAS with Nsight. Read the JAX Scaling Book sections on rooflines, GPU performance and transformer scaling as the bridge from kernels to system-level reasoning.

    Done whenyour tiled matmul is profiled with Nsight and you can explain whether the gap to cuBLAS is compute, memory, occupancy or instruction efficiency.
  4. Weeks 15–1911 Jan – 14 Feb

    Inference systems with CS229S and GPU MODE

    Follow CS229S on transformer systems, arithmetic intensity, prefill vs decode, KV caching, speculative decoding and parallelism. Pair it with selected GPU MODE lectures on profiling, FlashAttention, Tensor Cores, fused kernels, NCCL and quantization. Build one reusable benchmark harness reporting TTFT, TPOT/ITL, throughput, p50/p95 latency and GPU memory. Use Zero-to-SGLang for the completed fundamentals of KV cache, prefill/decode and inference benchmarking.

    Done whenKV caching and speculative decoding work, with measured speedups and a written explanation of why prefill and decode stress hardware differently.
  5. Weeks 20–2215 Feb – 7 Mar

    vLLM, scheduling and quantization

    Start with Fast & Efficient LLM Inference with vLLM, then trace the vLLM docs/source for PagedAttention, continuous batching, prefix caching, chunked prefill, scheduling and speculative decoding. Use 100 Days of Inference for block allocators, prefix-cache experiments and quantization exercises. Study tiny-vLLM as a reference implementation, not something to copy. Compare BF16/FP8/weight-only quantization on latency, throughput, memory and quality.

    Done whenyou can explain how scheduling and KV-cache capacity move TTFT, throughput and tail latency—not just report a benchmark number.
  6. Weeks 23–248 Mar – 21 Mar

    Sizing, benchmarking and a capstone

    Do NVIDIA's Sizing LLM Inference Systems course from its Generative AI / LLM learning path. Use the Scaling Book's inference section for model/KV-cache sizing and the parallelism tradeoffs. Build a small inference engine that adds, where practical, KV caching, batching/continuous batching, prefix caching, quantization and speculative decoding. If two GPUs are available, add tensor parallelism and inspect NCCL overhead.

    Done whenyou have a public repo, a benchmark report, an architecture diagram, and a short write-up explaining exactly why your engine is slower or faster than vLLM.

Alongside the plan

Practical lab spine

100 Days of Inference is the experiment bank: pull only the entries that match the phase. It covers inference mechanics, kernels, serving, caching, quantization, parallelism and production.

Systems side-track

Read matching chapters from Backend from First Principles and System Design Primer: queues, caching, backpressure, load balancing, concurrency, scaling and observability. Keep this to ~1 hr/week.

Keep open throughout

Machine Learning Systems by Vijay Janapa Reddi remains the reference text. CMU 11-868 LLM Systems is the optional bridge into broader serving, compression and distributed LLM systems.

Do not add more courses

Skip generic GenAI, LangChain, RAG, agents, prompt-engineering and broad ML bootcamps for now. The target is still low-level compute, inference algorithms and systems performance.
